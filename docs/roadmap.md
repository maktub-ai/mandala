# 产品路线与当前范围

确认日期：2026-10-09。本文区分已确认方向、当前交付和待讨论问题，不代表未来功能已经实现。

## 当前交付：Personal 本地使用

继续完善现有个人本地版，本轮补齐全站响应式 Web 界面。聊天、任务、审批和停止是重点；Agent、项目、资料、MANA、市场及系统设置在小屏上也应可操作。

验收覆盖 320px、390px 手机宽度、768px 平板和桌面布局；导航可打开和关闭，内容与表单不被裁切，弹窗可滚动，输入、保存和取消可触达。宽表格、代码和组织图可在自身区域内滚动。复用同一套组件、业务状态与接口。

响应式回归用例见 [responsive.spec.ts](../tests/e2e/responsive.spec.ts)，包括短窗口审批与停止、触摸消息操作、任务验收、目录选择和配置保存。浏览器测试使用隔离数据与模拟 CLI；真机浏览器和原生 CLI 的实际验收分别进行。

服务和原生 CLI 仍在本机运行。响应式页面不等于手机已经可以跨网络连接：本轮不改变回环监听、接入鉴权或部署方式。

## 已确认的后续方向

2026-10-14 补充确认：文件与记忆的本地版约定。文件入口以最近文件为中心，汇总已提交附件和明确发布的产物；指定文本可在会话摘要完成后检查更新。先完善本地客户端、后端与存储，官方云后续部署；当前不承诺文件跨设备同步。

- 远程访问现有实例：其他设备通过 Web 或 CLI 控制当前执行机上的工作。
- 一次性设备配对、保持登录、按设备撤销；用户身份与设备授权应分别建模。
- 后续协作优先采用 B1：成员共用工作区和执行环境，按角色限制操作。按用户隔离原生 CLI 账号、文件系统和执行环境是另一项更大范围的设计。
- 不依赖 Tailscale，也不要求用户安装私人组网客户端。跨网访问仍须有可达入口；设备主动连接接入服务或团队后端是候选方案，尚未定稿。
- Personal 开源版、Teams 自部署版和 Teams 托管版作为长期产品路线；团队的账号、成员、角色、操作记录与执行机连接需要另行设计。

## 暂缓开发、后续讨论

| 事项 | 待确认内容 |
| --- | --- |
| 个人远程接入 | 首版只支持自部署入口，还是同时提供我们运营的托管入口；会话数据、中继内容、认证和运维的边界 |
| Teams 代码开放范围 | 自部署 Teams 的协作能力是否完整开源，托管与自部署如何共用核心；用户尚未对具体开放范围作最终选择 |
| Teams 服务 | 登录、邀请、角色权限、审批责任、操作记录和不同团队的数据隔离 |
| 独立执行机 | 后端与执行端分离、机器注册、任务路由、断线恢复、停止确认和原生账号归属 |
| 实际远程验收 | 至少两台真实设备，覆盖配对、发起工作、审批、停止、断网重连及授权撤销 |

不把路线图中的候选机制提前实现为通用框架。开始下一切片前，单独确认目标、规格和验收条件。

## 源码与版本管理

沿用 [协作与发布流程](collaboration.md)：`main` 为统一主线，`work/<功能>` 为短期功能分支，审阅和检查后合入；发布版本用标签记录。
