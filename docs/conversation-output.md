# 对话公开输出合同

适用范围：Chat 本轮过程、对话卡片及关联 Task 的最新公开文字。原生执行状态、对话关闭标记和 Task 验收各自保持原有职责；文字展示不会完成、重开或验收 Task。无需数据库迁移。

## 数据与分类

- 原生 `commentary`、`final_answer`、`partial_answer` 是分类依据，不按文字内容猜测。明确标记的答复可以流式显示；`commentary` 始终保留在过程。
- 无 phase 时，运行中和等待审批期间显示“最近输出”。只有正常结束才把最后一段符合条件的公开文字确认为最终答复，较早文字仍是过程。
- 错误、中断、截断或异常停止保留已收到的文字，并标记本轮未完成，不把残缺内容包装成完整答复。
- 同一 `itemId` 的增量累积为一条文字，保留首次出现的 key 和位置；原生 `item/completed` 的完整快照覆盖累积值，避免工具事件穿插造成分段、重复或残缺。
- 最新文字仅取公开 assistant 文字及显式进展上报；不从 reasoning、analysis 或工具结果提取。Chat 原有技术详情、推理摘要展示仍按各自原有合同处理。

`shared/conversation-output.ts` 统一分类与最新文字投影；`src/runView.ts` 将其接入本轮时间线，`server/conversation-progress.ts` 为列表和 Task 使用同一规则。

## 轮次与来源

- 每轮独立读取。新轮尚无公开文字时保持为空，不借用上一轮输出；旧上报和迟到的旧 run 事件不能成为当前进展。
- 投影携带 `runId`、来源事件 ID 和来源时间。是否标为历史同时核对执行状态与当前执行 ID，读取本身不追加进展事件。
- 取最新公开过程文字作为预览；已确认的最终答复不覆盖过程预览。只有一条无 phase 答复时，正常结束后允许预览为空。
- 可选的 `progress report` 继续支持显式步骤。普通公开进展直接在对话输出，CLI 无需为使文字可见而调用上报工具；步骤完成不代表 Task 完成或验收。

## 展示与刷新

`ExplicitProgressView` 区分“过程说明”“最近输出”“进展上报”及历史来源，并显示原始时间。卡片和 Task 摘要最多显示三行，完整公开文字可在 Chat 查看。关联 Task 摘要标明来源对话，当前来源优先于历史来源。

Chat 本轮过程的外层历史及每项工具的输入／输出详情，在运行、失败、中断和完成状态下都默认收起，由用户显式点击展开。流式事件与状态变化不自动展开，也不覆盖当前组件中的手动展开／收起状态；刷新后重新收起。

收起历史时，运行中或未完成轮次仍展示最新公开进展预览；当前操作、失败／中断等异常操作的紧凑摘要、错误和待处理审批继续可见。工具摘要可展示目标或单行最新输出，完整输入／输出仍需展开；待处理审批保留操作上下文和可执行按钮。

Chat 沿用现有 SSE；列表沿用三秒轮询。服务端按事件游标与状态缓存投影，未变化时不重读完整事件历史，文字或生命周期变化时重新计算。该扩展不另建推送通道。

## Compact C 与验证边界

本次为现有 Compact C 的局部扩展：沿用中性语义颜色、共享图标、折叠控件和既有字体；正文为 14px / 1.6，来源与时间使用紧凑辅助层级。没有新的全局调色、字阶或控件体系，因此保持 `PRODUCT.md`、`DESIGN.md` 不变；当前 checkout 缺少 `.impeccable/design.json`，本次不补建。

文档核查已覆盖上述共享投影、服务端缓存、`runView`、`TurnProcess`、`ExplicitProgressView`、关联 Task 摘要、样式和轮询入口，并对照现有产品及设计合同。对应回归包括 phase 分类、流式累积、completion 覆盖、轮次隔离、隐私来源排除、生命周期独立性，以及 Chat / 卡片 / Task 联动。

本轮测试、构建、E2E 和视觉复核的最终结果以外部交付证据为准。浏览器证据使用合成数据和真实后端，覆盖 1440px / 390px、深浅主题及 Chat / 卡片 / Task；不等同于安装版或全应用验收。

CLI 证据分层：四种 Mandala 链路十二轮的事件回放验证分类合同；OpenCode 因产品禁用仅有原生 ACP 证据。不据此宣称安装版五种 CLI 全链路通过。截图及实验原始数据保留在本地，不进入仓库。
