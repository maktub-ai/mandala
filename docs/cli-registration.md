# Desktop terminal command

The desktop Settings command action explicitly registers `~/.local/bin/mandala` on macOS and Linux. It uses the App's bundled Node and CLI; a separate Node installation is unnecessary. Web and Windows clients report registration unavailable. No installer or App startup silently changes PATH or shell profiles.

The bounded `mandalaDesktop.cli.status()` and `.install()` preload methods return registration and login-PATH status. The main process accepts only these actions from its own main frame and local App origin. The renderer cannot supply a path, shell command, runtime port, or credential. Installation does not imply the bare `mandala` command is available: PATH omission and an earlier executable with the same name are reported separately. The returned quoted absolute command remains usable. Shell aliases and the environment of an already-open terminal may differ from the login shell checked by the App.

The fixed user-local directory must be owned by the user, without symlinks or group/public write access. Creation is exclusive. Existing foreign files, directories, symlinks (including dangling links), and hard-linked files are preserved. An owned regular launcher whose complete bytes match the managed template is recognized after an App move or configured workspace change. It is preserved rather than overwritten: the user must manually remove the displayed old launcher before explicitly registering the new location. A staged, fully written file is published exclusively; write failures leave the previous command intact and do not leave an unusable target fragment.

The launcher quotes executable paths and forwards arguments unchanged. It records the configured workspace path, never credentials or a runtime port. The bootstrap honors explicit `MANDALA_HOME` / legacy `OPEN_MANA_HOME`, Agent invocation context, and explicit base URL options/environment according to existing CLI precedence. Otherwise it reads the selected workspace's private desktop record and authenticates the existing runtime with its challenge-response probe. Missing, stale, starting, forged, or unreachable records fail closed. There is no fallback to port 4332 and no second runtime is started. Help works while the App is closed. Actual CLI requests continue to use the existing local-access credential mechanism.

Only synthetic homes under `/tmp` are used by registration tests. Real HOME registration and installed-App acceptance belong to the final delivery gate.
