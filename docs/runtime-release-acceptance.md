## Run order and evidence packet

1. Freeze the exact package and record source SHA, version, OS build and architecture, artifact SHA-256, and signature/trust result. For every row record exact vendor package version, source and resolved launcher identity (redact personal paths), bridge version, and approval/credential **mode** only. Do not copy secrets, raw sessions, or private paths into Git. Check launch on the packaged desktop, not a development shell; an already working terminal does not pass I.
2. Repeat vendor-free P and missing-launcher controls on the candidate before spending any model credits. Prove the allowlist and loopback containment before the backend starts. Use synthetic local credentials only. On Windows use an approved pre-existing disposable offline environment or equivalent pre-entry OS enforcement. Give Codex an explicit runtime fixture PATH **before first probing or sending**; ambient PATH cannot prevent registered PATH refresh. Treat unexpected PowerShell, executable, egress, or prompt as a failure; don't enable Windows Sandbox, alter registry/PowerShell policy, or run an unguarded package to get a pass. Existing test remains Mac-only; Windows mocks stay labeled source evidence.
3. For real P, in a separately approved isolated setup, stop at the checkpoint in the table. These checkpoints require no model turn but do **not** guarantee a vendor CLI won't start background services or make network requests; assume no auth/network permission during offline QA. If the checkpoint requires login, network, or unapproved provider state, stop and record the blocked boundary. Do not import from personal profiles or bypass the host's trust policy.
4. For F, use only a pre-approved vendor configuration, host, spend limit, and a disposable empty project. Disable automatic title/memory, unneeded tools/hooks/MCP, and dependent follow-up work. Send one short no-tool request in Mandala, require an attributable answer plus terminal success in the same conversation, and check the adapter did not retry, fall back, or ask for an unexpected permission. Capture only a redacted receipt and record auth or cost blockers instead of trying another provider. If vendor setup is missing, leave F blank rather than substituting a fixture result.
5. Attach the dated receipt to the release's QA item with `pass / blocked / failed / not run` for each level and OS. If a platform or runtime was not qualified, keep that limitation explicit; no summary “all supported” from a partial matrix.

Do not add a managed installer merely because the upstream documentation provides a shell script. A separate prerequisite is eligible only after a release-reviewed, platform-specific artifact pin, digest, publisher evidence, redistribution/operation review, and explicit install choice. Verify before extraction and activation, disallow arbitrary archive entries or lifecycle commands, leave system PATH and existing installs untouched, and handle removal or rollback independently of sign-in.
